# Verify Concilium

Every check here runs offline. No API keys, no network, no real `claude`/`codex`/`gemini`/`opencode` binaries, and nothing reads or writes your home config.

## Commands

Run from the repo root. This is the same sequence CI runs (`.github/workflows/ci.yml`).

```bash
npm ci                                       # clean install from the lockfile
npm run build                                # core, then cli (tsc)
npm run typecheck                            # core + cli project refs and tests, desktop --noEmit
npm test                                     # vitest in cli, core, desktop, then the repo invariants
npm run lint -w concilium                    # eslint in desktop (warnings are allowed, errors are not)
node packages/cli/dist/bin/concilium.js --help   # the built CLI starts
```

All six commands must exit 0. A change is not verified until they do. To be sure nothing depends on your working tree, run them in a fresh clone:

```bash
rm -rf /tmp/concilium-verify
git clone --branch <branch> <repo> /tmp/concilium-verify && cd /tmp/concilium-verify
```

Faster loops while working:

```bash
npm run test -w @concilium/core              # core only
npm run test -w @concilium/cli               # cli only (needs a built core)
npm run test -w concilium                    # desktop only (needs a built core)
npm run test:repo                            # repo invariants only (needs a built core)
npx vitest run packages/core/src/services/deliberation-service.test.ts
npx vitest run packages/core/src/domain/code-council/   # playbooks, classifier, rubric, playbook-step check, ranking, judge choice (picked and configured) and parsing, graft parsing, synthesis.md, divergence and reframe questions
npx vitest run packages/core/src/domain/verification/ packages/core/src/adapters/gate-runner.test.ts   # gates, verify.yaml, integrity checks, validity rule
npx vitest run packages/core/src/adapters/git-worktree-workspace.test.ts   # worktrees, commits, revert, patch and mergeability check, gc
npx vitest run packages/core/src/services/code-service.test.ts   # candidates, verification, the adversarial round, reports, ranking, synthesis, reframe and configured roles on real temp repos
npx vitest run packages/core/src/domain/roles/ packages/core/src/services/role-service.test.ts   # role specs, factory.yaml roles, --role flags, precedence and the role map
npx vitest run packages/cli/src/commands/code.test.ts            # concilium code end to end on fake CLIs, and concilium roles (needs a built core)
```

The CLI tests, the desktop tests and the repo invariants import `@concilium/core` (and `@concilium/core/providers`) from `packages/core/dist`. After changing core, run `npm run build:core` before them.

## How the offline harnesses work

- **Deliberation e2e** (`deliberation-service.test.ts`) builds a real `DeliberationService` with a real `CliCouncilGateway` and swaps only the agent CLIs: every driver is a `FakeCliDriver` whose `respond(brief)` answers by role. A Stage 1 brief gets a fixed plan or an error. A council brief (its task names `council-prompt.md`) reads that file from `brief.cwd`: a ranking prompt (it ends with "provide your code review and ranking") gets a ranking that puts the preferred plan first; anything else is the chairman and gets a fixed synthesis. Don't key on `FINAL RANKING:`, since the synthesis prompt quotes the juror rankings. Config, secrets and run history use the real `JsonConfigStore`, `PlaintextSecretStore` and `JsonRunRepository` in a `mkdtemp` directory. `OPENROUTER_API_KEY`, `COUNCIL_MODELS`, `CHAIRMAN_MODEL` and `OPENROUTER_API_URL` are stubbed empty so the temp config is the only source, and no key is set. To test a new pipeline behavior, add a case there and assert on the returned `RunRecord`, the recorded events, the briefs in `driver.runs`, or what `JsonRunRepository` reads back.
- **Through the composition root** (`config-service.test.ts`, `create-concilium.test.ts`, `role-service.test.ts`): `createConciliumRuntime` with real JSON stores in a temp dir, and every entry of `runtime.drivers` replaced by a `FakeCliDriver`, including the CLIs the test does not run (set `detection: { installed: false }`), because the runtime calls `detect()` on every driver when it fills in a default council, default agents or default implementers. `fetch` is stubbed with `vi.stubGlobal` to act as OpenRouter (SSE for streaming juror calls, JSON for the chairman) and records every request. Use this when the behavior depends on runtime wiring, the default council, the default agents, role resolution or the real `OpenRouterGateway`.
- **Roles in tests** (`role-service.test.ts`, `code-service.test.ts`, `code.test.ts`, `concilium.test.ts`): for resolution, make a temp repo dir with a `.git` directory (it bounds the upward search for `.concilium/factory.yaml`; without one the search walks up to `/`), write `factory.yaml` there, save roles with `runtime.configService.saveRoles(...)`, build flags with `parseRoleFlags([...])`, and stub `COUNCIL_MODELS`/`CHAIRMAN_MODEL` empty. For a code run, pass `roles` to `runCodeCandidates` as `{ ...defaultCodeRoles(['claude', 'codex']), judge: { value: 'codex:gpt-5.2', source: 'flag' } }` and assert on `record.roles`, the driver that ran (`driver.runs`, and `opts.model` for the role's model), `Judgment.judge`/`sameFamily`/`sameFamilyReason`, `synthesis.picker`, each graft's `integrator`, and `adversarial.adversaries` (`lane`, `provider`, `model`, `peers`). An adversary of a family no candidate has attacks every candidate, so its tests count for all of them; make them regression guards (pass on the base) when the test needs them counted. In `code.test.ts` the `roles` cases use their own repo (`roles-repo`) so its `factory.yaml` reaches no other case; restore the file with `git checkout` after making it invalid, and delete `$XDG_CONFIG_HOME/concilium` after `config set`, since the CLI cases share the sandbox config.
- **Code runs on real temp repos** (`git-worktree-workspace.test.ts`, `code-service.test.ts`, `gate-runner.test.ts`, `gc.test.ts`, `code.test.ts`): each test `git init`s a repo in a `mkdtemp` dir, with `GIT_CONFIG_GLOBAL` (or `HOME`) pointing at a sandbox git config and `GIT_CONFIG_NOSYSTEM=1`, and a worktree root in the sandbox. In `code.test.ts` the fake `claude` answers the framing run when `council-prompt.md` exists in its cwd (and logs its argv to `framer.log`), and otherwise logs its cwd and edits files; the fake `codex` writes `half.js`, deletes `sum.test.js` and exits 1. Assert on the record, the branches (`git show <branch>:<file>`), and that `git status --porcelain` and `HEAD` of the checkout are unchanged.
- **Gates in tests** (`gate-runner.test.ts`, `code-service.test.ts`, `code.test.ts`): commit a `.concilium/verify.yaml` whose gates are small `node` scripts (one that passes on the base, one that already fails there, such as `node lint.js` exiting 1), so no package manager runs. A `GateRunner` gets the test's git env through `new GateRunner({ env })`. In `code.test.ts` the CLI's `PATH` holds only the fake bin dir, so write gate commands with the absolute Node path (`JSON.stringify(process.execPath)` inside a single-quoted YAML string); `/bin/sh` is called by absolute path. To test an install step, use a command such as `mkdir node_modules`, never `npm ci`. Assert on `record.verification` (plan, baseline) and each `candidate.verification` (`status`, `newFailures`, `disqualified`, `penalties`, gate verdicts and `sha`, findings with `rule`, `path` and `evidence`).
- **Adversaries in tests** (`code-service.test.ts`, `code.test.ts`): the adversarial round runs only when the plan has a test gate, and an adversarial file only counts if that gate's command picks it up, so make the `test` gate a small `run-tests.js` (`RUN_TESTS` at the top of `code-service.test.ts`) that `require`s every `*.test.js` and exits 1 if any throws (`node sum.test.js` would never run the copied file, and every test would pass on the base). In `code-service.test.ts` tell an adversary from a candidate by its brief (`brief.task.startsWith('You are an adversary')`): it writes its test files under `brief.cwd` and `concilium-adversarial.json` (`{"tests": [{"files": [...], "specClause": "..."}]}`), and can read the peers' patches from the `Candidate diff, read-only: <path>` constraints while it runs. In `code.test.ts` the fake CLIs act as adversaries when their cwd's basename starts with `adv-`. Families come from the provider registry (`claude` → `anthropic`, `codex` → `openai`, `gemini` → `google`), so test ids are `anthropic-1`, `openai-1`. Assert on `record.adversarial` (`matrix`, `tests[].validity`, `survival`, `runs` with `sha` and `output`, `adversaries[]` with `peers`, `notes`, `errors`), that the tests are on `concilium/<run>/adv-<family>`, and that each candidate's branch head and `git status --porcelain` in its worktree are unchanged.
- **Judges in tests** (`code-service.test.ts`, `code.test.ts`): a judge runs only with `judge: true` (the CLI passes it unless `--no-judge`) and only for an exact tie, so give two candidates different code that passes the same gates and acknowledges every playbook step (`1. done` ... `4. skipped: ...` for `feature`) when the test needs a `PASS` report. The judge is a plan brief whose `council-prompt.md` starts with `You are judging`: split it on `## Candidate ` (the first character of each part is the letter) and answer `{"scores": [{"candidate", "criterion", "score", "reason"}]}` for every letter and criterion, scoring by something in that candidate's diff, never by its position. The criteria are the frozen rubric's: the playbook's when the framer fails, the tailored ones when it answers, so a fake judge must score the same criteria the run froze. A candidate fake must not answer that prompt as a framing run: in `code-service.test.ts` candidates answer every plan brief with an error, so the rubric is the playbook's and the judge is a separate fake (`gemini`, so it is of another family). The judge is picked by `detect()` over the drivers in registry order: every `FakeCliDriver` is installed and signed in unless given `detection`. In `code.test.ts` the fake CLIs answer `--version`, `auth status` and `login status`, because picking a judge runs detection in the CLI's cwd (the repo); a fake that does not would run its code path there. To test a rubric changed after freezing, mutate `frame.rubric.criteria` in `onFramed`. To make a tied family judge, install only the tied CLIs and give one candidate fake a judging mode (`agent(..., { prefer, prompts })` in `code-service.test.ts` answers a plan brief whose prompt starts with `You are judging`), or configure it as the `judge` role. Without a judge, or when it does not order the tie, the smallest diff wins: give candidates diffs of different sizes (or the same size, so the id decides). Assert on `record.ranking` (`order` with `rank`, `status`, `key`, `size`, `judgeTotal`; `winner`, `reason`; `judgments` with `judge`, `sameFamily`, `sameFamilyReason`, `rubricSha256`, `scores`, `totals`), on `candidate.report` (a `judge` evidence line after a same-family judge), on the prompt the judge fake recorded, and that the judge fake's `runs` is empty when no judge should run.
- **Synthesis in tests** (`code-service.test.ts`, `code.test.ts`): synthesis runs only with `synthesis: { runDir }` (the CLI passes the run's data dir unless `--no-synthesis`), `verify`, at least 2 candidates and a winner, so pick the winner deterministically (`judge: false` and the smallest diff). The graft picker is a plan brief whose `council-prompt.md` starts with `You are choosing grafts`, picked like the judge (another family than the base and the donors when one is usable, so a separate `gemini` fake in `code-service.test.ts`; the configured `judge` role when set); it answers `{"grafts": [{"candidate": "A", "files": [...], "hunk"?, "instruction", "why"}]}` with files from that candidate's diff (in `code.test.ts` the fake `claude` takes the first `+++ b/<path>` under `## Candidate A`). The integrator is the base's CLI (or the configured `integrator` role) on a code brief whose task starts with `You are integrating`, run in the worktree named `integration`; read the graft id from the `Graft graft-<n>:` line and write that graft's files, so a test can seed a graft that breaks a gate. The grafts are re-verified with the same gates and, when the test gate passes, the `evidence`/`regression-guard` adversarial tests, so a seeded breaking graft is rejected with gate evidence (and a test regression when a valid test passed before). A synthesis test must not diverge: keep one candidate failing no adversarial test of another family (or no adversarial round), or the run ends in `reframe-needed` before any graft. Assert on `record.synthesis` (`base`, `branch`, `headSha`, `picker`, `notes`, `dropouts`, each graft's `status`, `commitSha`, `revertSha`, `reason`, `evidence` and `integrator`, `checks`, `patchPath`, `mergeable`, `mergeCheck`), on the integration branch's history (`git rev-list base-head..integration`) and files, on `result.patch` (`git apply --check` in the checkout) and on the text of `synthesis.md`.
- **Reframe in tests** (`reframe.test.ts`, `code-service.test.ts`, `code.test.ts`): the divergence check runs only with `synthesis: { runDir }` and a type other than `prototype`, after ranking. To make `disjoint-survival` fire end to end, give two candidates of different families code for two readings of one acceptance line that both pass the gates, and have each family's adversary write a test of its own reading quoting that line as `specClause` (a `run-tests.js` test gate, `judge: false` so the order is fixed): each test fails on the base, passes only on its author's candidate (`own-family-only`), and each candidate fails the other's. The phraser is the planner (by default the first agent's CLI and model) on a plan brief whose `council-prompt.md` starts with `You are phrasing spec questions`; answer `{"questions": [{"clause": "<line exactly as listed>", "question": "..."}]}`, or an error to get the fallback. In `code.test.ts` an `AMBIGUOUS` file committed to the repo switches the fakes to the two readings (`claude` `-`, `codex` `_`), so that case runs last in `concilium code`. For `no-gate-pass` and `judge-spread` use `detectDivergence` directly with `DivergenceCandidate`s, tests, a matrix and `Judgment`s. Assert on `record.status`, `record.reframe` (`divergence` with `trigger`, `detail` and `conflicts`; `questions`; `phraser`; `source`; `notes`; `reportPath`), on `record.synthesis.skipped`, that no integration branch and no `result.patch` exist, on the text of `reframe.md`, on the prompt the phraser recorded, and on the CLI exit code (2).
- **Fake agent CLIs on `PATH`** (`subprocess.test.ts`, `cli-drivers.test.ts`, the four driver tests, `concilium.test.ts`, `code.test.ts`): write a small Node script named after the binary into a `mkdtemp` dir and make it executable (`0o755`). Its first line must be `#!${process.execPath}`, so it runs on the same Node without looking anything up, and the `PATH` the driver or CLI gets must contain only that temp dir (`createHeadlessCliDrivers({ PATH: binDir })`, or `env: { ...sandboxEnv, PATH: binDir }` for the CLI; `code.test.ts` symlinks `git` into it). Never append the real `PATH`: a real `claude`/`codex`/`gemini`/`opencode` would then run when a fake is missing. The script answers `--version` and the auth status command (`auth status`, `login status`, `auth list`) for detection, and for a run prints the CLI's own JSON stream (replay a fixture from `cli/__fixtures__/` or build lines inline: a `claude` `{"type": "result", ...}` line, or `codex` `item.completed` with an `agent_message` then `turn.completed`); env vars, argv or a marker file in its cwd control its exit code and stderr. To check flags, have it append its argv to a file in the sandbox.
- **CLI** (`concilium.test.ts`): spawn `bin/concilium.ts` through the `tsx` loader with `HOME` and `XDG_*` pointed at a temp dir and an env that holds no API keys. Set `PATH: ''` when the command could reach an agent binary, or `PATH: <fake bin dir>` for a run on fake CLIs.
- **Ink components** (`CostSummary.test.ts`): render the component with Ink's `renderToString` and assert on the text. Keep these as `.test.ts` with `React.createElement`; the CLI `tsconfig.json` excludes only `*.test.ts` from the build.

## When to add or update tests

- **Changed a CLI flag, command or description:** run `npx vitest run packages/cli -u`. Read the snapshot diff and confirm every line of it was intended, then commit the `.snap` file with the change. Run it again after the last wording change, so the committed snapshot matches. Update `packages/cli/README.md` (options table) and any doc that shows the command, or `npm run test:repo` fails. Keep a command description to one line in the top-level `--help` list: a wrapped line that starts with a word and a comma reads as another command to the docs check.
- **Changed deliberation, ranking, prompts, the council or persistence:** add or extend a case in the offline e2e or a co-located unit test (`file.ts` → `file.test.ts`). Default-council rules go in `council-members.test.ts`; how the runtime applies them goes in `config-service.test.ts`.
- **Changed a role, its validation, its keyword, its default or the precedence:** extend `roles.test.ts` (pure) with a case that must pass and one that must be rejected (naming the problem), then `role-service.test.ts` for the layer order and where the file is found. A change to which judge or adversary runs goes in `code-service.test.ts` (the configured judge, adversary, picker and integrator cases) and must keep a judge of a family it reads flagged `sameFamily` with its reason: the cross-family rule is a warning plus a flag, never silently another CLI. A change to the role table, the warnings or the error exits goes in the `roles` cases of `code.test.ts`; a change to the jurors or chairman from `factory.yaml` in `concilium.test.ts`.
- **Changed a playbook, the classifier or the rubric rules:** extend `playbooks.test.ts` or `rubric.test.ts`, then run `npx vitest run packages/core/src/services/code-service.test.ts -u` and read the brief snapshot diff: playbook steps reach candidates verbatim, so every changed line is a change in what agents are told. A changed number of steps changes what `missingPlaybookSteps` expects; check the `runCodeCandidates ranking` and `code.test.ts` report reasons.
- **Changed worktrees, commits, reverts, the patch, the mergeability check or `gc`:** extend `git-worktree-workspace.test.ts` on a real temp repo, and `gc.test.ts` when the CLI output or exit code changes. Never point a test at the repo you are working in. Keep asserting that `checkPatch` leaves the user's index and working tree as they were.
- **Changed gate detection or `verify.yaml`:** extend `gates.test.ts` (it reads a fake file tree, no disk). **Changed how gates run** (env, timeouts, output, install): extend `GateRunner.runLane` in `gate-runner.test.ts`. **Changed an integrity rule:** add a case to `GateRunner.integrity` with a real commit that triggers it and one that must not (a false positive is as bad as a miss), and keep `disqualify` only for weakening tests. **Changed the verdict or the CLI summary:** extend the verify case in `code-service.test.ts` or `code.test.ts`.
- **Changed the validity rule, survival or the manifest format:** extend `adversarial.test.ts` (pure, no disk) with a row per case, then check the end-to-end matrix in `runCodeCandidates with adversarial`. A change to which tests count also changes `disjoint-survival`: check `reframe.test.ts` and `runCodeCandidates reframe`. **Changed how adversaries run or how their tests are placed in a lane:** extend that case, and keep asserting that candidate branches and worktrees are unchanged after the round. **Changed the adversary brief:** it is what every adversary is told; check the brief assertions there and the README section.
- **Changed the ranking order, the winner rule, the tie break or what a report counts:** extend `ranking.test.ts` (pure) with a case per rule, keeping the property that dropping every judgment changes only the order inside tie groups (the smallest-diff tie break also acts only inside the top tie group), then the matching case in `runCodeCandidates ranking`. **Changed the judge** (choice, prompt, answer format, the rubric hash check): extend `judging.test.ts`, keep asserting that the prompt names no CLI or family and holds no example ordering, and check the tie and hash-mismatch cases end to end. **Changed the ranking or report output of the CLI:** extend `code.test.ts`.
- **Changed the graft prompt, the graft answer format, the integrator brief or `synthesis.md`:** extend `synthesis.test.ts` (pure), keep asserting that the graft prompt and the integrator brief name no CLI or family, then check `runCodeCandidates synthesis`. **Changed when a graft is rejected or how it is re-verified:** extend that case with a seeded graft that must be rejected and one that must stay, and keep asserting the integration branch's history (each graft one commit, a rejected one followed by its revert) and that the patch still applies. **Changed the synthesis output of the CLI:** extend `code.test.ts`.
- **Changed a divergence trigger:** extend `detectDivergence` in `reframe.test.ts` with a case that must fire and one that must not (a false reframe stops a run that could ship, a miss ships a blend), keep `runCodeCandidates synthesis` at `status: 'done'`, and check `runCodeCandidates reframe`. **Changed the reframe prompt, the answer format, the fallback questions or `reframe.md`:** extend the `reframe questions` cases there, keep asserting that every line in conflict gets exactly one question, then check both reframe cases end to end. **Changed the reframe output or the exit code of the CLI:** extend the reframe case of `code.test.ts` and the README (`It exits ...`).
- **Changed driver output parsing:** add or extend a recorded fixture in `adapters/cli/__fixtures__/` and assert on the normalized events and the report.
- **Changed how an agent CLI cost is shown:** keep the `est. API-equivalent` label (`AGENT_COST_LABEL` in `packages/cli/src/ui/format.ts`, `AGENT_COST_LABEL`/`AGENT_COST_LABEL_SHORT` in `desktop/src/renderer/utils/analytics.ts`) next to it, and extend `CostSummary.test.ts` for CLI output.
- **Fixed a bug:** first write a test that fails on the bug, then fix it. If the bug has a skipped `BUG:` test, unskip it instead.
- **Found a bug you are not fixing:** keep the failing test as `it.skip` with a `BUG:` comment, add it to the known-bugs table above, and report it.
- **Added an agent CLI:** add it to `PROVIDERS` (with its `family` and `models`) and give it a definition in `DEFINITIONS` in `adapters/cli/cli-drivers.ts` and a color in `desktop/src/renderer/providers.ts` (the typecheck fails until you do both). Put the argument building and line parsing in pure functions and test them with recorded fixtures and a fake binary on `PATH`. Never call the real CLI in tests. Update the registry order in `create-concilium.test.ts` and `providers.test.ts`, and the list of valid CLIs in the `roles.test.ts` error messages. Its `family` also decides which adversary it gets in the adversarial round, which adversarial tests count against it (and so whether it can diverge from another candidate), whether it can judge a tie or pick grafts as another family, and whether it is flagged as a configured judge or rejected as a second adversary of one family.
- **Added a gateway adapter:** keep it behind `LlmGateway` and route to it from `CliCouncilGateway` by member spec. Never call the real service in tests.
- **Added license headers to old files:** lower `MISSING_HEADER_BASELINE` in `scripts/repo-invariants.test.mjs` to the count it reports.

## Rules for tests

- Assert on public outputs: the `RunRecord` or `CodeRunRecord`, the events emitted, the briefs a driver received, the files and branches written, the CLI's stdout, stderr and exit code. Don't assert on private helpers or call counts unless the count is the contract.
- Check that a new test catches a defect: break the code it covers once, see the test fail, then restore the code.
- No network, no real binaries, no `~`, no API keys: use temp dirs, fake CLIs on a `PATH` that holds only their temp dir, and pass `HOME`/`XDG_*` overrides to any spawned CLI (see `concilium.test.ts`).
- Silence the logger in tests that exercise noisy code: `beforeAll(() => setLogLevel('error'))`.
- New `.ts`/`.tsx` files need the MIT license header (see `AGENTS.md`); the repo invariants enforce it.
- Core source is scanned for imports by a regex, test files included: a string literal like `'… from '` followed by a quote in a core file reads as an import of an undeclared package, and so does a string that ends in `from` followed by a quote (`'… to graft from'`, or a test name such as `'... where each came from'`). Reword it (the diff parser uses a regex for `rename from`/`rename to` for this reason).
- In docs, a flag-like word inside a quoted example task (`concilium code "add a --dry-run flag"`) reads as a flag of that command to the docs check. Write the task without the dashes.
